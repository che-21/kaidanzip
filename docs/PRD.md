| --- | --- |

## 1. 제품 개요

### 1.1 한 줄 정의
장면별 연출표 마크다운 1개와 장면 이미지 폴더를 넣으면, 내레이션·움직이는 이미지·빨간 강조 자막·배경음·효과음을 합쳐 45~58초 9:16 유튜브 쇼츠(MP4)를 만드는 로컬 CLI.

### 1.2 배경
괴담 쇼츠는 "첫 3초 후킹 → 긴장 고조 → 반전 → 여운" 형식이 정해져 있어 반복 제작에 적합하다. 하지만 한 편마다 녹음, 이미지 움직임, 자막 타이밍, 효과음 배치를 손으로 맞춰야 한다. MD2Short는 사람이 쓴 연출표와 준비한 이미지를 그대로 받아, **실제 음성 타이밍에 맞춘 합성**만 자동화한다.

### 1.3 v1 비전
- 연출표 1개 + 이미지 N장 → 업로드 가능한 한국어 괴담 쇼츠 1편.
- 실제 내레이션 음성의 문자 타임스탬프를 기준으로 자막·효과음·장면 전환을 맞춘다.
- 렌더 전에 사람이 타이밍 표를 확인하고 y/n으로 결정한다.
- 모든 산출물을 `jobs/<job_id>/`에 남겨 재현·디버깅·비용 추적이 가능하게 한다.

### 1.4 차별점
- **연출표 그대로**: 나레이션은 글자 그대로 읽고, 화면 연출·효과음 문구는 키워드로 cue가 된다. AI가 대본을 바꾸지 않는다.
- **음성 기준 sync**: 연출표의 `[0~4초]`는 목표치로만 보여 주고, 실제 렌더 타이밍은 `words.json`이 결정한다.
- **재렌더 무료**: `md2short render <job_id>`는 TTS를 다시 부르지 않는다.
- **로컬 제어권**: 입력, API 응답 원본, 중간 산출물, 최종 MP4가 사용자 컴퓨터에 남는다.

## 2. 영상 스타일 규격 (단일 진실원)

| 항목 | 규격 |
| --- | --- |
| 화면 | 세로 9:16, 1080×1920, 30fps |
| 길이 | 45~58초. 벗어나면 저장은 하되 QC 실패로 표시 |
| 대본 구조 | 첫 3초 후킹 → 짧은 전개 장면들 → 반전/여운 + 짧은 구독 유도 (연출표 작성자가 책임) |
| 화풍 | 사용자가 준비한 장면 이미지. 한 영상 안에서 같은 그림체를 권장 |
| 움직임 | 천천히 줌인(기본), 패닝, 놀라는 순간 흔들림, 클라이맥스 글리치, 마무리 페이드아웃 |
| 비네팅 | 모든 장면에 화면 테두리 어둡게 |
| 목소리 | ElevenLabs 기본 voice ([`voice.md`](voice.md)) |
| 배경음악 | `assets/bgm`에 넣은 mp3. 볼륨 0.18, "정적" 연출 시 잠깐 끊김 |
| 효과음 | `assets/sfx`에 넣은 파일을 연출표 키워드로 장면 시작에 배치 |
| 자막 | 하단 22% 위, 오른쪽 15% 여백(쇼츠 버튼 회피), 3~5어절, 굵은 흰 글씨 + 검은 외곽선, 강조어 글자만 빨간색 |

기준 샘플: [`../sample.md`](../sample.md) + `emotion/` 이미지 6장 — 장산범 괴담 6장면, 약 50초.

## 3. 문제 정의

| 문제 | 현상 | v1 대응 |
| --- | --- | --- |
| 한 편 제작에 손이 많이 감 | 녹음·편집·자막을 매번 수동 반복 | 명령 1줄로 음성부터 MP4까지 |
| 공포 연출 타이밍 맞추기 어려움 | 효과음·흔들림·정적 위치 수동 조정 | 연출표 문구를 cue로 바꿔 장면 시작에 자동 배치 |
| 자막·음성 sync 어긋남 | 글자 수 추정 타이밍은 틀어짐 | TTS가 돌려주는 문자 타임스탬프를 단일 기준으로 사용 |
| 비싼 호출 낭비 | 입력 실수가 TTS 이후에 발견됨 | 검증·점검을 TTS 전에 끝냄, 재렌더는 TTS 없이 |
| 오류를 이해할 수 없음 | 영어 에러 코드 | 장면 번호와 해결 방법을 한국어로 안내 |

## 4. 목표와 비목표

### 4.1 목표 (v1)

| ID | 목표 |
| --- | --- |
| **G1** | 연출표 + 장면 이미지를 1080×1920 30fps MP4로 변환한다. |
| **G2** | 자막·효과음·장면 전환 timing은 실제 내레이션의 `words.json`을 기준으로 한다. |
| **G3** | 길이 45~58초를 지킨다. 벗어나면 렌더 전 확인 표에서 빨간 경고로 알린다. |
| **G4** | 렌더 전 사람 확인(y/n)을 거친다. `--yes`로 생략할 수 있다. |
| **G5** | 입력 오류는 TTS 호출 전에 장면 번호와 함께 멈춘다. |
| **G6** | 자동 QC(해상도, fps, 길이, 자막 tail sync, 렌더 길이, 산출물)를 기록한다. |
| **G7** | 모든 중간 산출물과 로그를 `jobs/<job_id>/`에 남긴다. |

### 4.2 비목표 (v1)
- 공개 서버 배포·다중 사용자. 웹 화면은 localhost 전용이다.
- AI 대본·주제 추천. 연출표는 사람이 쓴다 (장면 이미지는 업로드 또는 AI 생성).
- 무료 TTS 테스트 모드. 대신 `MD2SHORT_FAKE_TTS`(무음)로 흐름을 무료 점검할 수 있다.
- BGM·효과음 자동 생성/다운로드. 라이선스를 확인한 파일을 직접 넣는다.
- 엑셀 일괄 제작, 유튜브 업로드, 다국어.
- 실존 개인을 특정하는 콘텐츠, 고어 수준 묘사.

## 5. 타겟 사용자

### 5.1 Primary — 연출표를 직접 쓰는 괴담·미스터리 크리에이터
- 장면별 나레이션·연출·효과음을 직접 정하고, 이미지를 따로 준비한다.

### 5.2 Secondary — 비개발자 1인 채널 운영자 (v2)
- 버튼 위주 화면과 AI 대본이 필요하다. v2-backlog의 웹 화면 대상이다.

## 6. 사용자 시나리오

### 6.1 연출표로 만들기 (장산범 샘플)
1. `sample.md` 형식으로 연출표를 쓰고, `0_…png`~`5_…png`처럼 번호를 붙인 장면 이미지를 한 폴더에 둔다.
2. `uv run md2short run sample.md --images emotion/`을 실행한다.
3. 강조어가 나레이션에 없거나 이미지 수가 장면 수와 다르면, 음성 생성 전에 `[장면 N]` 오류로 멈춘다.
4. 음성 생성 후 장면별 목표 시간 vs 실제 시간, 이미지, 모션, 효과음 표를 보고 y를 누른다.
5. `jobs/<id>/output/ret.mp4`와 `qc_report.json`을 확인한다.

### 6.2 다시 렌더하기
1. 렌더 결과를 보고 BGM·효과음 파일을 바꾸거나, 확인 단계에서 n을 눌렀다.
2. `uv run md2short render <job_id>`를 실행한다. 음성은 재사용되고 이전 결과는 `edit/attempt_<n>/`에 보관된다.

### 6.3 무료 리허설
`MD2SHORT_FAKE_TTS=synth`로 실행하면 무음 내레이션으로 전체 흐름(자막·장면 전환·렌더)을 비용 없이 점검한다.

## 7. 기능 요구사항

| ID | 기능 | 제품 요구 |
| --- | --- | --- |
| **F-01** | 연출표 입력·검증 | `## 장면 N [a~b초] : 제목` + 나레이션/자막 강조/화면 연출/효과음을 파싱한다. 장면 0개, 번호 비연속, 나레이션 누락, 강조어 불일치, 이미지 수 불일치는 TTS 전에 오류. |
| **F-02** | 장면 이미지 매칭 | `번호_이름.png/jpg` 파일을 번호순으로 장면에 대응하고 job 안에 복사·해시 기록한다. |
| **F-03** | 내레이션 음성 | ElevenLabs `with-timestamps`로 `audio/narration.mp3`를 만든다. |
| **F-04** | 자막 시간표 | TTS 문자 타임스탬프를 단어로 모아 `transcripts/words.json`에 저장하고 모든 timing의 단일 진실원으로 쓴다. |
| **F-05** | 연출 cue 자동 배치 | 화면 연출 → 모션/효과, 효과음 → SFX/BGM 정적 cue로 바꿔 장면 시작에 배치한다. |
| **F-06** | 배경음·효과음 폴더 | `assets/bgm`, `assets/sfx`에서 이름 규칙으로 고른다. 없으면 경고 후 계속한다. |
| **F-07** | 공포 자막 | 뜻 덩어리 단위 분할(문장 끝 필수 분리, 쉼표·대사 우선, 꾸밈말·동사 덩어리 보호, 3~5어절 목표), 덩어리의 첫 어절 시작~마지막 어절 끝 표시, 버튼 비침범 위치, 굵은 글씨 + 외곽선, 강조어 글자만 빨간색. AI 분할(검증) → 실패 시 규칙 분할, 연출표 `자막 분할` 줄의 "/"로 수동 지정. `md2short subtitles`로 TTS 전 미리보기. |
| **F-08** | 렌더 전 확인 | 타이밍 비교 표 + y/n. n이면 렌더하지 않는다. |
| **F-09** | 합성·출력 | Remotion으로 합성해 `output/ret.mp4`에 저장한다. |
| **F-12** | 말 속도 조절 | `--speed 0.7~1.2`. 길이가 규격을 벗어나면 확인 단계에서 맞는 값을 제안한다. |
| **F-13** | 웹 화면 | `run_web.bat` / `streamlit run webapp/app.py` → 대본 확인(자막 "/" 수정) → 이미지 확인 → 음성·타이밍 → 영상(진행률·재생·다운로드·QC). |
| **F-14** | AI 장면 이미지 | 공통 화풍 + 장면 화면 연출로 OpenAI 이미지 생성, 장면별 다시 만들기, 업로드와 섞어 쓰기. 안전 정책 거절 시 한국어 안내. |
| **F-15** | GitHub 로그인 | 웹 화면을 GitHub OAuth로 보호. 허용 목록에 있는 ID만 접속, 작업마다 소유자 기록·본인 작업만 표시. 설정이 없으면 로그인 없이 로컬 전용. |
| **F-10** | 재렌더 | `md2short render <job_id>`로 TTS 없이 다시 렌더한다. |
| **F-11** | 자동 QC·상태·로그 | `qc_report.json`, `status.json`, `logs/`를 남긴다. |

## 8. 비기능 요구사항

| 항목 | 요구사항 | 검증 기준 |
| --- | --- | --- |
| 설치 | Python(uv), Node.js만 있으면 된다. FFmpeg 설치 불필요(Remotion 번들 사용). | README 절차 |
| 자막 정확도 | 마지막 단어 종료 vs 음성 길이 ±1000ms, 렌더 길이 vs 의도 ±3 frames | `qc_report.json` |

| 비용 | 실행 1회 = TTS 1회. 재렌더·리허설은 0회 | `logs/elevenlabs_tts_raw.json` |
| 보안 | API 키는 `.env`로만. `.env`는 git 제외, 로그에 키 없음 | `.gitignore` |
| 재현성 | job 안에 입력 사본·이미지 해시·중간 산출물 보관 | `jobs/<job_id>/` |
| 관측 가능성 | 실패 단계·원인·QC를 파일과 터미널에서 확인 | `status.json`, `logs/` |
| 라이선스 | 폰트·BGM·효과음의 상업적 이용 가능 여부는 사용자가 확인 | 업로드 전 체크 |

## 10. 미해결 질문
- 실사풍 이미지를 쓸 때 유튜브 "변경되거나 합성된 콘텐츠" 표시 안내 방식.
- 실존 지명·실제 사건이 얽힌 괴담의 금지 기준.
- 연령·수익 제한을 피하기 위한 이미지·대사 금칙 기준.
- 자막 폰트 라이선스 확정(현재 시스템 글꼴 Malgun Gothic 사용).

## v2-backlog (v1 범위 밖)

- **웹 화면 확장**: 공개 배포·로그인, [폴더 열기], 여러 job 동시 진행.
- **AI 모드**: 주제 입력·오늘의 괴담 주제 추천, LLM 대본·장면 구상·업로드 제목/설명/해시태그 생성, 장면별 [다시 쓰기].

- **테스트/실전 모드**: Edge-TTS 무료 음성 + 임시 이미지 → 실전 모드 전환과 비용 비교.

- 성공 지표 후보: 비개발자 첫 영상 성공률 ≥ 80%, 장면 이미지 재생성 평균 ≤ 2회.
